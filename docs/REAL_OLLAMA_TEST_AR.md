## الإعداد على Mac أو Linux

من جذر نسخة المشروع بعد نسخ الملفات المرفقة:

```bash
python3 --version  # يتطلب المشروع Python 3.11 أو أحدث
python3 -m venv .venv
.venv/bin/pip install -e '.[test]'
```

ثبّت Ollama من https://ollama.com/download إذا لم يكن متوفرًا. افتح التطبيق على Mac، أو شغّل `ollama serve` على الخادم إذا لم تكن الخدمة تعمل. لا تشغّل نسخة ثانية إذا كانت الخدمة تعمل بالفعل.

```bash
ollama list
```

اختر اسم نموذج محلي موجود كما يظهر في القائمة. إذا لم يوجد نموذج، نزّله صراحةً أولًا؛ مثال اختياري، وليس افتراضًا بأنه مثبت أو مناسب لجهازك:

```bash
ollama pull llama3.2
```

التنزيل يحتاج شبكة ومساحة وموارد لتشغيل النموذج. السكربت لا يثبت Ollama ولا ينزّل نموذجًا ولا يبدأ الخدمة تلقائيًا.

```bash
bash scripts/run_real_ollama.sh --model llama3.2
```

أو لخادم Ollama محلي آخر:

```bash
bash scripts/run_real_ollama.sh --model YOUR_INSTALLED_MODEL --url http://YOUR_LOCAL_SERVER:11434
```

استخدم خدمة موثوقة على شبكة خاصة؛ السؤال يُرسل إلى عنوان الخدمة المحدد. لا تستخدم نموذج cloud إذا أردت إثبات التشغيل المحلي. رفض remote_host في بيانات القائمة فحص مساعد، وليس إثباتًا تشفيريًا لهوية النموذج.

## ما يجري التحقق منه

1. استعلام `/api/tags` وفحص وجود الاسم المحدد قبل إرسال السؤال. نقص الخدمة أو النموذج فشل واضح برمز خروج غير صفري، وليس نجاحًا أو تجاوزًا.
2. تشغيل نواة المشروع الأصلية في عملية مستقلة، بمفتاح مؤقت وقاعدة SQLite مؤقتة، على loopback فقط.
3. سؤال عربي إلى `/chat` باستخدام Ollama الفعلي المحدد، والتحقق من جواب نصي غير فارغ.
4. مقارنة نص السؤال والجواب حرفيًا بين HTTP وSQLite، مع سجل طلب مكتمل.
5. إعادة الطلب بنفس `request_id` والتحقق من نفس الإجابة وعدم تكرار الرسائل.
6. إيقاف النواة وتشغيلها بالقاعدة نفسها، مع مزوّد غير متاح عمدًا: استعادة التاريخ وإعادة الطلب يجب أن تنجح من الحفظ.
7. إنشاء نسخة احتياطية مشفرة واستعادتها إلى قاعدة أخرى، ثم تشغيل النواة عليها وإعادة فحوص التاريخ ومنع التكرار مع المزوّد غير المتاح.

تُحذف قواعد التجربة والنسخة المشفرة المؤقتة بعد التشغيل. تبقى `report.json` و`core.log` في مجلد جديد تحت `data/live-ollama-*` (متجاهل في Git). يحتوي التقرير السؤال والجواب؛ لا تستخدم سؤالًا حساسًا. لا تُكتب مفاتيح API أو كلمة مرور النسخة في التقرير. يمكن تحديد `--output` بمجلد جديد؛ لا يُسمح بالكتابة فوق تقرير سابق.

## الوقت والجودة وحدود الإثبات

`latency_seconds` يقيس الزمن الكلي لأول طلب ولإعادات الطلب باستخدام ساعة monotonic. يشمل وقت الشبكة والنواة وتحميل النموذج إذا كان باردًا. لا يمثل وقت أول رمز، ولا tokens/sec، ولا متوسطًا إحصائيًا. النواة الحالية غير متدفقة؛ يحتفظ السكربت بمهلة HTTP الأصلية 90 ثانية والمهلة الكلية 100 ثانية، ويمنح عميل الاختبار 110 ثوانٍ. النموذج البطيء قد يفشل بهذه الحدود؛ لم تُغيّر كي لا نخفي سلوك المنتج.

`generation_received` يعني وصول إجابة من الخدمة المحددة، وليس إثباتًا مستقلاً لهويتها؛ المسؤول عن التشغيل يجب أن يوجّه السكربت إلى Ollama حقيقي. `contains_arabic` مؤشر حروف فقط. `quality: NOT_EVALUATED` يبقى كما هو: دقة الجواب وفائدته تحتاج قراءة بشرية. `PASSED` لا يظهر إلا بعد نجاح كل فحوص الحفظ والاستعادة وإعادة الطلب. إذا حصل توليد ثم فشل فحص لاحق يبقى الوضع `FAILED`.

## الاختبارات التي لا تحتاج نموذجًا

```bash
.venv/bin/python -m pytest -q
```

الاختبار الحقيقي متجاوز افتراضيًا. لتفعيله عبر pytest:

```bash
RUN_LIVE_OLLAMA=1 OLLAMA_MODEL=llama3.2 .venv/bin/python -m pytest -q -s tests/test_live_ollama_optional.py
```

للاحتفاظ بدليل في مسار واضح استخدم سكربت التشغيل؛ نسخة pytest تضعه تحت مجلد pytest المؤقت.

`test_ollama_failure_paths.py` يحقن عشرة أعطال بشكل حتمي: رفض الاتصال، انقطاع البروتوكول، مهلة القراءة، مهلة الاتصال، HTTP 404 و500، JSON تالف، حقل جواب مفقود، جواب فارغ، وانتهاء المهلة الكلية. لكل منها يتحقق من عدم حفظ نصف محادثة، حالة failed، نجاح إعادة الطلب نفسه بعد التعافي، وعدم استدعاء المزوّد مرة أخرى عند إعادة الرد المكتمل. هذه محاكاة أخطاء نقل ومهلة، وليست فصل شبكة عن نموذج حقيقي أو انتظارًا فعليًا لمدة 90/100 ثانية. تتوقع 502 لأخطاء HTTPX بما فيها المهلة، و504 للمهلة الكلية، وفق الشيفرة الحالية.

`test_live_ollama_runner.py` يختبر السكربت كاملًا مع خادم محاكاة، إضافة إلى غياب النموذج وحماية تقارير سابقة. نجاحه لا يثبت تشغيل نموذج. لم تتغير اختبارات المحاكاة الأصلية.

المراجع الرسمية: https://docs.ollama.com/api/tags و https://docs.ollama.com/api/chat
