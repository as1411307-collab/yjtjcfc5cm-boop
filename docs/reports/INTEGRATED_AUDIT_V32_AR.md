## 3. حدود مسار التعلّم

- لا يمنح صلاحيات جديدة للنماذج ولا يقرأ تفكيرها الداخلي المخفي. يسجل **المدخل/المخرج الملاحظ** وحالة التحقق بوصفها `unverified` ما لم يوجد دليل مستقل.
- قاعدة `learning_events` إضافية في نفس SQLite، لا خدمة أو نواة ثالثة ولا Vector DB.
- النص يُحفظ أصلاً في `messages`. يسجل التعلّم معرفات الرسائل والبصمات، لتجنب المضاعفة. عند حذف المحادثة تختفي النصوص من المصدر، لكن **البيانات الوصفية والبصمات تبقى**.
- API القراءة **محمية بمفتاح**؛ ملف ZIP لا يتضمن النص إلا إذا طلبه المستخدم مع `include_content=true`. الحد: 200 حدث و5 ميجابايت نص JSONL قبل الضغط لكل صفحة.
- النقل أسبوعياً إلى Mac **يدوي** عبر مشاركة الهاتف أو رابط API مصادق؛ لا يوجد جدولة موثوقة أو رفع تلقائي أو سياسة حذف تلقائي. يجب حفظ الملفات في مساحة خاصة مشفرة.
- لا يمكن تأكيد نجاح بحث/أداة أو صحة مصدر لم يُنفّذ فعلياً؛ أحداث التدقيق الموجودة لا تُمنح تصنيف `verified` تلقائياً.

## 4. نتائج التحقق التي ينبغي عدم الخلط بينها

- **تاريخ v31**: نجاح CI Python/Swift/iOS Simulator مثبت في `43969389175`؛ التقرير القديم يذكر اختبار نموذج Ollama محاكي، لا LLM حقيقياً.
- **اختبارات v32**: يعتمد الحكم النهائي على آخر SHA لفرع الإصلاح، وليس نجاح تشغيل قديم قبل تغييرات الواجهة/التغليف/WAL.
- **iOS**: النجاح الآلي يعني بناء Simulator غير موقع؛ لا يثبت Face ID أو تسجيل ميكروفون فعلي أو تبديل سماعات Bluetooth أو تعامل المقاطعة ولا الإصدار إلى TestFlight.
- **الأمن**: API بمفتاح واحد؛ الموافقة المسجلة في قاعدة البيانات ليست مصادقة Secure Enclave ولا مفتاح توقيع مستخدم على الخادم.
- **الاعتماديات**: أمن المورد وتراخيص المكتبات المرجعية الخارجية في `kimi` ليس مثبتاً بمجرد نجاح بايثون أو Swift.

## 5. المخاطر المفتوحة (لا يجوز وصفها محلولة)

1. **نشر الخدمة**: اختبر HTTPS/Tailscale وعزل منافذ Ollama على شبكة فعلية، وعدم كشف API أو Langflow للإنترنت.
2. **حقيقة النموذج**: شغّل اختباراً طوعياً مع Ollama حقيقي وتحقق من الاستجابة والتخزين والتعامل مع الزمن والأخطاء.
3. **أمن الجهاز**: تحقق على iPhone فعلي من القفل، الأذونات، تسرب ملفات ShareLink، المقاطعة الصوتية، وتغيّر الشبكة.
4. **التصديق بالوجه**: توثيق التوقيع المحلي لا يكفي لإثبات توقيع Secure Enclave صالح ومُتحقق منه على الخادم.
5. **الذاكرة طويلة الأجل**: تسجيل الأحداث يتراكم دون تصفية تلقائية لمدة 60–90 يوماً؛ يلزم قرار سياسة احتفاظ/حذف واضح لاحقاً.
6. **استهلاك الذاكرة**: حد backup الحالي قد يصل إلى 1GiB، والتشفير AES-GCM يتم دفعة واحدة في الذاكرة؛ لم يُحلّ ذلك بتقييد القراءة فقط.
7. **الأرشيفات الخارجية**: Kimi يحوي ملفات مصدرية وتراخيص متعددة وأرشيفات كبيرة؛ مراجعتها من حيث الحق في إعادة التوزيع وحقن التعليمات سابقة لأي استيراد.
8. **تكامل الموافقات**: أوامر الوكيل الحالية محدودة بالمهام/التسمية/التثبيت؛ لا يوجد broker شامل للأدوات أو موافقة على تنفيذ خارجي.
9. **التوزيع**: ما زالت هناك حاجة لاختبار Wheel المثبت في بيئة منفصلة بعد CI، وتجربة التطبيق الموقّع على iPhone حقيقي.
10. **نسخ التاريخ**: تنظيف Kimi لم يزل بيانات الملفات من تاريخ Git؛ لا يُعلن التخلص من تاريخ حساس أو تقليل حجم الاستنساخ قبل إجراء مخصص ومراجعة.

## 6. سياسة الدمج

- يُفتح Pull Request **مسودة** للفرع V32 مقابل `main`؛ يشمل أساس v31 المتقدم والتغييرات الجديدة.
- تبقى تصحيحات `fix/shared-required-tables` و`fix/export-backup-size-limits` التاريخية مراجع مقارنة فقط؛ نُقل المبدأ الصحيح إلى v32 من دون الرجوع إلى نسخة قديمة من `core/app.py`.
- تبقى وثائق المستودعات الثلاثة الأخرى في PRs منفصلة مسودة لتجنب دمجها بوصفها تطبيقات شغالة.
- لا دمج تلقائياً إلى `main` ولا نشر إنتاجي قبل مراجعة نهائية للنتائج والقيود المتبقية.

**مبدأ القرار:** إصلاح عطل قابل للإثبات، والحفاظ على مسار تشغيل واحد واضح، وتقليل التكرار بدلاً من جمع كل المكتبات في تطبيق واحد.
